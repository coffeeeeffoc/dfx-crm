# pnpm Monorepo Implementation Plan

**Goal:** 将 CRM 改为 pnpm 管理的多包仓库，保留 mock 演示行为，推送 main/dev 自动验证前端并从 main 部署 GitHub Pages。

**Architecture:** `apps/web` 承载 Vite + React 前端；`apps/api` 只保留空 TypeScript 项目，不启动服务、不实现接口；`packages/core` 复用现有纯 TypeScript 业务模型/权限/字段；`packages/mock-data` 复用现有演示数据生成器。单个 Git 仓库、单份 pnpm 锁文件，子包通过 `workspace:*` 引用。

**Tech Stack:** Node.js 24、pnpm 12.6.0、TypeScript、Vite、React、GitHub Actions / Pages。

## 1. 迁移目录与依赖

- 移动 `src/`、`index.html`、`vite.config.ts`、`tsconfig.json` 到 `apps/web/`。
- 把 domain/access/records/material-fields 移到 `packages/core/src/`，seed 移到 `packages/mock-data/src/`；更新所有调用方、测试和 `scripts/export-field-registry.ts` 的包引用。
- 根 `package.json` 只组织 workspace 命令和材料工具依赖；web 管理 UI/Vite 依赖，core/mock-data/api 各自提供类型检查。
- 创建 `pnpm-workspace.yaml`、统一 TypeScript 配置和锁文件，删除 npm 锁文件。录音、缓存、构建产物继续忽略。

## 2. 保留 mock 行为

- 前端始终使用本地 mock 初始数据；保留 localStorage/IndexedDB，既有本机业务数据不清空。
- 不引入后端请求、服务器、数据库或虚假的启动命令。
- 共享 mock 包增加独立性与关联数据检查；迁移后的现有 32 项测试全部执行。

## 3. 自动构建与部署

- `.github/workflows/frontend.yml` 在 main/dev push、PR 和手动运行时安装锁定依赖、测试、类型检查、Vite 构建。
- 使用 Vite 的 `--base=/dfx-crm/` 构建 Pages 资源；继续使用现有 hash 路由。
- main 上传 `apps/web/dist` 并部署到 github-pages；dev 只构建，不覆盖正式站点。Pages 不上传材料或转录稿。
- 用户已明确授权将源码仓库公开，含现有材料与 Git 历史；启用 Actions Pages 发布源。

## 4. 验证与交付

- `pnpm install --frozen-lockfile`、`pnpm test`、`pnpm typecheck`、`pnpm build`，检查产物相对目录与静态页面。
- 浏览器检查生产产物的工作台、菜单导航和 mock 列表。
- 更新 README / 验证记录，提交并将同一提交推送 main 和 dev。
- 检查两个分支的 Actions 结果、main Pages 部署提交号，访问线上页面和静态资源，确认 mock 内容可见。
