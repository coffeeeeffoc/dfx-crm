# 星谱 CRM 前端原型

## 输入与范围

- `materials/CRM-Counting Stars2.xlsx`：19 个工作表。目标流程、字段、确认内容和角色矩阵。
- 28 张截图（编号 21–52，部分不连续）：现有客户/联系人、商机、报价、合同/台账、服务单、库存/借还、日志。
- 三段 WAV：逐段本地识别后保存在 `materials/transcripts/`，保留时间戳；识别不等于人工逐字校对。
- 当前没有应用、Git 仓库或 CodeGraph 索引；不覆盖原始材料。

## 方案

采用一个 React + TypeScript + Vite 应用。桌面使用 antd；移动端使用 antd-mobile TabBar、SearchBar、Popup、Button 等。业务数据和计算共用，断点切换呈现方式。相比双应用无需维护两份业务逻辑；相比单纯缩放桌面表格，手机能直接记录沟通。

侧栏分为工作台、销售管理、业务协同、组织管理。浅灰背景、白色内容面板、蓝色主操作，紧凑但留白清楚。首页聚焦待办、销售漏斗、来源、重点项目和动态。列表提供搜索、筛选、创建、详情与导出；核心流程可完整演示。

## 数据与操作

- 线索保留来源细分和推荐人，可分配、转跟进项目。原线索保留。
- 客户允许同单位多联系人，查重依据电话/微信、邮箱、姓名+单位；软删除可恢复，标签分公共/个人。
- 跟进项目七阶段为 0/10/20/50/70/90/100%，独立签单概率计算预期金额。记录沟通、下一次提醒、放弃原因、转公海/领取均保留历史。
- 报价计算明细、折扣和运费；订单呈现收付款和成本；售前售后、库存借还、供应商、学习提交审核、日志、统计具备演示操作。
- 模拟数据用虚构联系人及 example.com 邮箱；不把原图中的银行卡、电话直接植入公开构建。
- 状态保存在浏览器 localStorage；附件保存在 IndexedDB，不实现后端。显式捕获读写失败，禁止失败后伪装保存成功。
- 角色切换只演示权限；默认主管。生产鉴权、服务器审计、IP 白名单、备份、消息推送另做。

## 优先级与待确认

以“确认内容”工作表的明确答复优先；其余页用于补充。存在差异：流程说明中的全部数据按本人/下属可见，与确认内容的客户基础资料共享；无机会归档与不需要归档状态；主来源分类；修正时间窗口未定。原型将基础客户共享、跟进按归属显示，并在需求映射中记录差异，不宣称生产安全隔离。

## 验证

检查 TypeScript/生产构建。对金额、查重、归属流转、领取不重复、移交快照做最小单元检查。浏览器验证桌面及手机视口，新建线索→转项目→记录沟通→转公海→领取，及刷新持久化。录音输出需检查段落数量、时间覆盖及原始识别保留。
