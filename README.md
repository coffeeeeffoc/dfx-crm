# 星谱 CRM 前端原型

基于 `materials/CRM-Counting Stars2.xlsx` 的 19 个工作表、28 张现有系统截图，以及 3 段会议录音制作。主线为线索、客户、跟进项目与公共池；报价、订单、服务、库存、学习和日志提供配套演示。

## 启动

需要 Node.js 22.12+（或 24 LTS）和 npm。

```powershell
cd I:\dfx-crm
npm ci
npm run dev
```

打开 <http://localhost:5173>。开发服务监听局域网；同网络手机可使用终端打印的 Network 地址，Windows 防火墙需允许该端口。

```powershell
npm test          # 核心业务逻辑检查
npm run build    # TypeScript + Vite 生产构建，输出 dist/
npm run preview  # 查看生产构建
```

## 技术与数据

- Vite + React + TypeScript。
- 桌面表格、表单、详情、弹窗使用 Ant Design；移动导航、搜索、沟通弹层和部分操作使用 Ant Design Mobile（adm）。小于 768px 切换卡片列表。
- 默认系统管理员，右上角切换演示用户，其角色与直属领导由“系统管理”配置；移动端切换入口在“更多”。
- 系统管理可配置企业全称、简称、Logo，新增/修改/删除用户，维护组织领导关系、动态角色和页面字段。普通用户统一查看本人及所有层级下属的数据，公共池等共享资料按规则例外。
- 权限按菜单 → 列表/详情/编辑弹窗/沟通弹窗/收付款/财务区域 → 操作和字段配置；字段支持隐藏、只读、可编辑。同一字段在不同区域可采用不同权限。
- 业务数据保存在当前浏览器的 localStorage，附件保存在 IndexedDB；刷新后保留。首次进入使用演示数据。
- 联系人、电话、邮箱和交易为演示数据；未导入原始截图中的银行账户等信息。人员/品牌沿用需求材料作为演示词汇，人员归属不代表真实组织现状。
- 同一网站地址下共享本机数据。`localhost`、`127.0.0.1`、局域网 IP 是不同存储空间，不会同步。清理站点数据会清除演示记录与附件。
- 系统管理支持导出业务 JSON，**不含附件文件**。当前没有 JSON 恢复入口。
- 原始材料、转录稿和模型缓存不进入 `dist/`，Vite 开发服务也禁止通过文件路径访问这些目录。

## 推荐演示路径

1. 新建线索，选择已有客户或同时新增客户，记录来源与首次沟通。
2. 将线索转为项目；原线索继续保留。
3. 在项目中调整预算、概率、阶段，记录沟通并安排下次跟进。
4. 填写放弃原因并转公共池，重新领取，检查历史沟通保留。若由其他顾问领取，原顾问可看移交前快照。
5. 在报价中添加产品明细；在订单中逐笔登记回款；在库存中借出和归还。
6. 在学习档案中保存草稿、提交审核、主管发布；在日志中查看自动汇总并填写总结。
7. 在数据统计中切换分组、日期和图表；在客户档案中预览 Excel 导入或导出列表。
8. 在系统管理中复制一个角色，隐藏项目详情的预算字段、设编辑弹窗预算为只读，绑定用户后切换身份检查。
9. 新增项目自定义字段并填写；停用后页面隐藏，恢复后原值保留。修改用户直属领导，检查本人及下属的可见范围变化。

## 第二轮补齐

已逐项核对 Excel、28 张截图及三份转录。新增费用与成本、市场与行政、基础资料，补充联系人/合同/服务/借还字段、线索导入、无机会直接转池、沟通修正与季报。

各业务页顶部“筛选查询”支持时间范围、负责人、创建人/创建时间、更新人/更新时间和关键业务字段组合；主列表可选择显示更多字段。工作台统计卡片旁的明细图标可打开同范围记录并导出。

- [材料逐项核对表](docs/materials-audit.md)：19 张工作表、28 张截图、确认内容和录音定位，订单 51 列对应关系。

## 这一版的边界

这是可操作的前端原型，没有后端、登录、真实消息通知、多人实时同步、真实权限隔离或服务器备份。切换角色只是界面演示，全部数据仍存于浏览器。财务为人民币简化口径，正式税费、汇率、奖金和佣金规则见需求待确认项。

录音已全部处理，但为机器识别，未逐字人工校对或识别说话人；人名、品牌、重叠发言需对照原音。已标注发现的明显异常片段。
